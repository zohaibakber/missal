# Effect APIs for Missal

Reviewed on 2026-09-30 against the published `effect@4.0.0-rc.118` source archive. Checked 84 named candidates across core effects, resources, fibers, queues, caches, streams, atoms, SQL, schemas, and metrics. Also inspected filesystem interfaces and Missal's existing runtime and RPC ownership. This is a use-case review, not a claim that every API improves performance.

The implementation order and measurements live in the [performance and resilience plan](performance-resilience-plan.md). Upgrade the aligned Effect packages and import paths first.

## Adopt where they remove existing coordination

| APIs                                                                          | Missal use                                                                                                        | Decision and verification                                                                                                                                                                  |
| ----------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Effect.forEach` with `concurrency` and `discard`                             | Install template batches and prepare independent preview work.                                                    | Bound inputs before traversal. Discard installation results after commit; collecting all decoded bodies defeats the memory limit. Keep one database writer.                                |
| `Effect.acquireRelease`, `Effect.scoped`, `Effect.ensuring`, `Effect.onExit`  | Own print windows, PDF tasks, listeners, temporary seed files, and import resources.                              | Put cleanup beside acquisition. Exercise completion, failure, interruption, and owner disposal.                                                                                            |
| `Effect.tryPromise`, `Effect.callback`                                        | Adapt filesystem pipelines, Electron callbacks, and cancelable browser APIs.                                      | Pass abort signals and register cleanup when supported. Promise wrapping alone does not cancel native work.                                                                                |
| `FileSystem.readFileString`, `stream`, `open`, `makeTempFileScoped`, `rename` | Read small manifests and bounded delta bodies; stream a fresh seed into a temporary destination.                  | Provide the narrow Node filesystem layer. Keep decompression bounded through a Node stream pipeline or a measured Effect stream adapter. Publish only under exclusive bootstrap ownership. |
| `FiberHandle.make`, `FiberHandle.run`                                         | Own one pack synchronization job or one cancelable task per session.                                              | Use `onlyIfMissing` for synchronization so another status read cannot restart it. Disposal owns interruption and reporting.                                                                |
| `FiberMap.make`, `FiberMap.run`                                               | Supersede obsolete previews by owner and dispose work for a closed window.                                        | Replacement interrupts the previous fiber for that key. Propagate cancellation across IPC. Keep accepted physical prints in their own ordered queue.                                       |
| `Semaphore.make`, `withPermits`, `withPermitsIfAvailable`                     | Limit PDF rendering and reject duplicate exclusive operations.                                                    | Bound admission and payload bytes separately. Waiting on a semaphore can still retain unlimited requests.                                                                                  |
| `Queue.make`, `offer`, `take`, `shutdown`                                     | Bounded accepted print jobs if the existing promise chain cannot express the policy cleanly.                      | Set capacity and overflow behavior explicitly. Bound suspended producers too. Never silently discard an accepted print or save.                                                            |
| `Effect.timeoutOrElse`                                                        | Typed deadlines for startup, reads, and preview preparation.                                                      | Define cleanup and an unavailable state. A write deadline leaves an uncertain outcome until the stored revision is reconciled.                                                             |
| `Effect.catchTag`, `catchTags`, `Schema.TaggedError`                          | Distinguish corrupt packs, missing optional resources, busy storage, revision conflicts, and unavailable workers. | Recover by error category. Keep defects observable and preserve interruption instead of treating it as successful pack installation.                                                       |
| `Atom.map`, `mapResult`, `family`; `useAtomValue` selectors                   | Subscribe to small results near their consumers.                                                                  | Profile commit counts and reads. Keep one source of truth for query results. The atom React hook supports selecting before subscription.                                                   |
| `Reactivity.mutation`, atom runtime reactivity keys                           | Refresh affected template summaries, fields, and document details after committed changes.                        | Batch invalidation after a transaction. Worker reactivity does not automatically notify the renderer; send one scoped commit notification through the bridge.                              |
| `Atom.batch`                                                                  | Publish related local atom updates without intermediate UI states.                                                | Batch the final acknowledged result and progress metadata. This does not make SQL writes transactional.                                                                                    |
| `Effect.yieldNow`                                                             | Give other worker fibers a turn between template batches.                                                         | Yield outside the write transaction. It does not preempt a large synchronous parse, release a transaction lock, or create another CPU thread.                                              |

Core behavior was checked in the [rc.118 Effect source](https://github.com/Effect-TS/effect/blob/effect%404.0.0-rc.118/packages/effect/src/Effect.ts), [filesystem interface](https://github.com/Effect-TS/effect/blob/effect%404.0.0-rc.118/packages/effect/src/FileSystem.ts), and individual queue, semaphore, and fiber modules from that release.

## Preserve and refine existing APIs

| APIs                                                                          | Existing use                                       | Refinement                                                                                                                                                                                                               |
| ----------------------------------------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `Context.Service`, `Layer.effect`, `Layer.provide`, `ManagedRuntime`          | Repositories and storage ownership.                | Add one pack lifecycle owner. Avoid creating a runtime per template, query, or component. Share the existing database service.                                                                                           |
| `Effect.fn`, `Effect.gen`, `Effect.withSpan`, `annotateLogs`                  | Named repositories and operation sequencing.       | Name pack planning, seed bootstrap, batch commit, and preview jobs. Use diagnostics that omit document content. Prefer ordinary functions for synchronous transforms.                                                    |
| `Schema.fromJsonString`, reusable schema decoders                             | IPC and stored envelopes.                          | Construct codecs once and validate at file, transport, and database boundaries. Schema JIT is already enabled. `DocumentEnvelope.state` is currently `Schema.Unknown`, so it does not validate every Lexical node.       |
| `Atom.setIdleTTL`, `keepAlive`                                                | Detail expiration and retained summary lists.      | Retain 100 small summaries if their measured cost is acceptable. Expire inactive bodies. TTL is not an absolute byte or entry limit.                                                                                     |
| `Atom.optimistic`, `optimisticFn`                                             | FIR document reorder and deletion.                 | Keep rollback and revision reconciliation tests. Apply only to operations with a correct reducer and failure policy.                                                                                                     |
| `Atom.fn`, atom runtime mutation functions, `Atom.Interrupt`, `Atom.Reset`    | Async mutations and UI results.                    | Audit default supersession behavior. A second write can interrupt an earlier non-concurrent computation. Choose explicit per-entity serialization or rejection for writes; replacement is useful for reads and previews. |
| `RpcClient.layerProtocolWorker`, `RpcWorker.layerInitialMessage`, `RpcServer` | The single storage worker and readiness handshake. | Keep one SQLite owner. Verify worker recovery semantics before adding a supervisor. Measure before replacing the JSON relay with operation-specific RPC.                                                                 |
| Drizzle `db.transaction`; `SqlClient.withTransaction`                         | Storage transactions.                              | Keep Drizzle transactions where used. Do not introduce a second transaction owner. Pack body changes, fields, and installation metadata commit together.                                                                 |

Atom behavior was checked in the [rc.118 Atom source](https://github.com/Effect-TS/effect/blob/effect%404.0.0-rc.118/packages/effect/src/reactivity/Atom.ts), the React hook implementation, and the project's [atoms](../src/state/atoms.ts). RPC and SQL APIs use the new `effect/rpc` and `effect/sql` paths in rc.118.

## Use only when profiling or behavior justifies them

| APIs                                                                                       | Possible use                                                                     | Gate                                                                                                                                                                                     |
| ------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Stream.fromIterable`, `mapEffect`, `grouped`, `runForEach`, `runDrain`; filesystem `sink` | A large resource stream or decompression adapter.                                | Prefer a byte-bounded loop for a finite 100-template manifest. If a stream wins, bound chunks, prefetch, and downstream buffers. Do not finish with `runCollect` when processing bodies. |
| `Cache.make`, `makeWith`, `get`, `invalidate`, `refresh`                                   | Deduplicate expensive immutable resource reads or revision-specific projections. | Cache by pack hash or the full document/value revision. Bound capacity and account for bytes. Do not duplicate atom body caches or keep 100 decoded templates.                           |
| `Effect.cached`, `cachedWithTTL`, `cachedInvalidateWithTTL`                                | Shared process-lifetime manifest initialization.                                 | Use when repeated loads are demonstrated. Avoid caching a transient failure forever or hiding pack changes.                                                                              |
| `Deferred.make`, completion and await APIs                                                 | A readiness barrier or per-batch completion signal.                              | Existing layer and RPC readiness already cover startup. Add a Deferred only when a distinct wait policy exists.                                                                          |
| `Atom.debounce`                                                                            | Reduce IPC search requests.                                                      | Debounce the query atom, not input state or save acknowledgement. The existing deferred local search needs measurement first.                                                            |
| `Atom.withFallback`                                                                        | Show an existing query result during initial loading.                            | It supplies a fallback while the primary result is initial. It is not a policy for hiding errors or revision conflicts.                                                                  |
| `Atom.pull`, `Reactivity.query`, SQL reactive queries                                      | Incrementally consume data that actually arrives as a stream.                    | No need for a 100-item summary catalog. Add only if the repository contract benefits from incremental results.                                                                           |
| `SqlResolver.request`, `findById`, `ordered`, `grouped`; request resolvers                 | Batch independent SQL lookups.                                                   | First find an N+1 pattern. `FirDocument.getMany` already performs one ordered batch query, so wrapping it adds little value.                                                             |
| `Effect.retry`; `Schedule.exponential`, `recurs`, `jittered`                               | Retry classified transient reads.                                                | Bound attempts and elapsed time. Do not retry a corrupt shipped artifact, revision conflict, uncertain write, or physical print.                                                         |
| `Metric.counter`, `gauge`, `histogram`, `update`                                           | Diagnostic queue depth, pack progress, and durations.                            | Keep labels bounded and diagnostics opt-in. Start with existing spans and performance marks if those answer the question.                                                                |
| `FiberSet.make`, `FiberSet.run`                                                            | Supervise multiple independent scoped jobs.                                      | The pack needs one writer job; previews need owner keys. Prefer the more specific handle or map for those cases.                                                                         |

Stream, cache, SQL resolver, and metric decisions are based on the corresponding source modules in the [published rc.118 release](https://github.com/Effect-TS/effect/releases/tag/effect%404.0.0-rc.118). The architectural gates above are recommendations for Missal, not upstream guarantees of speed.

## Avoid for this workload

- An unbounded `Queue`, `Effect.all` with unbounded concurrency, or a worker per template. These increase simultaneous allocations and compete for two CPU cores.
- `Atom.refreshOnWindowFocus` for immutable bundled resources. A pack changes with an app release, not whenever the window receives focus.
- A second live-query system beside atom invalidation. Cross-process ownership and notifications still need an explicit protocol.
- Distributed workflows, cluster infrastructure, network download services, and scheduling frameworks for assets already shipped with the app.
- Replacing synchronous document traversal with many tiny effects. Use typed boundaries and ordinary maps for field binding inside one serialized installer.
- Assuming a cache capacity is a byte budget, a fiber is a worker thread, or successful interruption proves that native work stopped.

## The template batch contract

Prepare only a bounded batch outside the write transaction. Recheck eligibility and revisions inside the transaction. Publish progress and invalidation after commit, release the prepared bodies, then yield.

```text
plan = compareManifestWithInstalledMetadata()
for each batch limited by template count and decoded input bytes:
    prepared = readAndDecodeEligibleBodies(batch, concurrency = 1)
    transaction:
        recheck user revisions and deletion markers
        resolve fields through one catalog index
        install prepared templates and matching metadata
        discard per-template return values
    publish one committed progress update
    release prepared bodies
    yield to other worker work
```

Start with four templates and four MiB of uncompressed input per batch. Tune both limits against the real corpus and worker memory. A large single document must have its own supported size limit; it cannot bypass the byte budget.

For first installation, prefer the seed path described in the plan so all 100 templates are ready without parsing 100 envelopes at runtime. The batch contract serves existing profiles, updates, and the fallback path.

# Missal

Rust 1.100.0 (`rust-toolchain.toml`), edition 2024, `unsafe` forbidden. No code comments. Tests only where behaviour cannot be checked by running the app.

Crates:

- `missal-core`: domain types, fields, dates, repository traits.
- `missal-store`: SQLite storage, migrations, embedded templates, seed data.
- `missal-text`: text layout and shaping on parley, embedded fonts, input widgets.
- `missal-docx`: `.docx` import.
- `missal-page`: paged layout and PDF output.
- `missal-editor`: rich-text editor view and model.
- `missal-auth`: email and password accounts against the Missal API (`MISSAL_API_URL`, compile time or run time): sign-in, rotating refresh sessions through `SessionKeeper`, password changes and the admin user calls. The session is cached in the OS keyring, 30 days offline.
- `missal-library`: client for the shared template library on the same API. Calls carry the access token from `SessionKeeper`.
- `missal-app`: the `missal` binary: shell, screens, preferences, printing, updates.

`cloud/`: the Missal API, deployed with Alchemy v2 (exact beta pinned in `cloud/package.json`) as an Effect `HttpApi` Worker. `cloud/src`: `Api.ts` contract (served as OpenAPI at `/openapi.json`), `Models.ts` `Model.Class` rows (password fields are `Model.Sensitive`, so they never reach JSON), `Accounts.ts` users and sessions, `Library.ts` templates, `Passwords.ts` PBKDF2-SHA256 at 100,000 iterations (the Workers WebCrypto ceiling), `Tokens.ts` 15-minute HS256 access tokens, `Auth.ts` middleware, `Handlers.ts`, `App.ts` wiring, and ports with Cloudflare and in-memory adapters: `Database.ts` (`Atomic` multi-statement writes: D1 `batch` live, a transaction in tests), `Blobs.ts` (R2), `Throttle.ts` (Workers Rate Limit binding). `Worker.ts` binds D1, R2, the rate limit (10 sign-ins per minute per IP, namespace 4721) and a nightly cron that purges expired sessions. Accounts are created by administrators with a temporary password that must be changed at first sign-in; there is no public sign-up. Roles are member, publisher (may publish templates) and admin (also manages people). Five wrong passwords lock an email for 15 minutes. The first sign-in that matches `MISSAL_ADMIN_EMAIL` and `MISSAL_ADMIN_PASSWORD` while no user exists creates the first admin. Refresh tokens rotate, and reusing an old one ends that session. A published template is a one-template `TemplateBundle`; installs are tracked in `library_links`.

Commands:

- Run: `cargo run -p missal-app -- --data-dir /tmp/missal-scratch [--seed 200]`. Always use a scratch `--data-dir`; `--seed` refuses the real one.
- Check: `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace`.
- Screenshots: `cargo run -p missal-app --features headless --example shots -- --out DIR` (also `editor_shots`, `perf`).
- Regenerate bundled templates from `templates/`: `cargo run -p missal-docx --example bundle` (writes `crates/missal-store/bundle/templates.bin`).
- Sign-in: set `MISSAL_API_URL` (compile time, run time or the root `.env`) to gate the app; debug builds without it skip sign-in and hide the library. Release builds refuse to compile without it. Only `https://` URLs are accepted, plus `http://127.0.0.1` and `http://localhost` for a local `vp run dev`.
- Release binary: `MISSAL_API_URL=https://… cargo build --release -p missal-app`, then `packaging/smoke.sh target/release/missal`.
- API service: in `cloud/` (Node 24.11.1 or later), TypeScript tooling is Vite+ (`vp`, config in `vite.config.ts`) on pnpm (pinned in `devEngines`, catalog and `allowBuilds` in `pnpm-workspace.yaml`): `vp install`, `vp check` (Oxfmt, Oxlint and type checks), `vp test` (HttpApiTest over in-memory SQLite with the real migrations), then `vp run dev` (local workerd, D1, R2, rate limit and cron) or `vp run deploy`. Sign in to Cloudflare once with `vp exec alchemy profile edit --add Cloudflare` (saved to `~/.alchemy/profiles.json`; state lives in Cloudflare); CI uses `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` instead. Both need `MISSAL_ADMIN_EMAIL` and `MISSAL_ADMIN_PASSWORD` in the environment or `cloud/.env` (see `cloud/.env.example`). The token signing secret is generated by `Alchemy.makeRandom` on first deploy and kept in state; destroying and recreating the stack signs everyone out. Sign-in hashes a password with 100,000 PBKDF2 rounds, which may exceed the Workers free plan's per-request CPU limit; Workers Paid avoids that.
- Set `CARGO_INCREMENTAL=0` and use the shared `target` directory only.

Releases (CI in `.github/workflows/ci.yml`, Velopack `vpk` version pinned there):

- Tags are `native-v*` and must equal the `missal-app` version. Old `v*` tags and the latest release belong to retired Electron installs, so never mark a native release as latest.
- Installers and updaters must never delete or move the data directory (`%APPDATA%\Missal`, `~/.config/Missal`).
- Restart for an update is allowed only when `Navigator::has_unsaved_changes` is false.
